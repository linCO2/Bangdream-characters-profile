## 四、脚本（全部位于工作区根目录 `人设工具\`）

调用方式：`node "人设工具\<脚本>.mjs"`。脚本以**自身位置**解析路径并读 `人设工具\_config.json`，与运行时的当前工作目录无关（已实测从 `C:\` 调用同样通过）。

| 脚本 | 作用 |
|---|---|
| `build_index.mjs` | 重建 `00_分块索引.json` |
| `bulk_extract_quotes.mjs` | 机械抽取全部台词 → 890 条候选（`07b_语录批量候选.md`） |
| `align_quotes.mjs` | 按「卡面ID + 篇号」把中文/日文单卡文件做块级同序对齐 → `ja_pairs.json`（49 篇 2015 块全部对齐） |
| `merge_quotes.mjs` | 精编 43 + 机抽评分筛选 94 → 137 条，并为机抽条目取同篇日文原句（`07_语录合并_raw.md`） |
| `render_quotes.mjs` | 解析合并 raw → `友希那_语录库.md` + `quotes.json` |
| `verify_quotes.mjs` | 逐字回检（中文对汇总/单卡/百科；日文对汇总或对齐池）→ `人设工具\verify_quotes*.json` |
| `render_card.mjs` | `友希那_人物卡片.json` → `友希那_人物卡片.md` |
| `sync_card_quotes.mjs` | 用语录库实际统计同步卡片 quotes 字段 |
| `qa_card.mjs` | 28 项质量校验 → `人设工具\qa_report.json` |

全部脚本用 DSH 自带 Node 运行，均已处理 UTF-8 BOM 与 CRLF。用法与扩展步骤见 `人设工具\人设流水线说明.md`。

## 六、语录库的两次修正（重要）

1. **智能体初稿 104 条 → 自检砍到 43 条**：它用脚本回检发现约半数的「中文台词」其实是自己的改写（源文件里找不到逐字对应），于是全部删除，只留机械验证 100% 命中的条目。**这是正确取舍**：宁可少于目标，也不交付伪原文。
2. **机械补足到 137 条 + 中日块级对齐**：43 条只覆盖 21/51 篇。用 `merge_quotes.mjs` 从源文件机械切句（按空行分段 → 拆完整句 → 去重 → 评分排序 → 每篇限流），补入 94 条机抽条目，覆盖 24/26 张有剧情卡面。
3. **日文对照从 46 条修到 136 条**：初始用「整句字符串命中」判定，只有 46/137 命中——因为官方中文常把日文拆成两句、或把「高み」译成「顶点」（例：`その一歩が、高みを目指す私たちにとって、重要なものになる` ↔「这一步对于以顶点为目标的我们而言，是非常重要的」）。改用 `align_quotes.mjs` 按「卡面ID + 篇号」做块级同序对齐（49 篇 / 2015 块全部对齐），机抽条目的日文对照从 3 条提升到 93/93。
4. **最终回检**：中文 137/137 逐字命中、精编 43 条中日双向 43/43、机抽日文对齐 93/93、出处 137/137 齐全、失败条目 0。卡面 10028（国服原创，无日文源）是唯一无日文对照的条目。

## 七、必须随卡片一起记住的素材事实

1. **说话人写法 86 种**：简繁（兰/蘭、纱夜/紗夜、薰/薫）与中日（莉莎/リサ、麻里奈/まりな）差异不归一就会重复计。
2. **素材文件头计数不可信**：`_汇总_中文.txt` 自称 49 篇，实际 51 篇。
3. **「中文汇总」不等于全中文**：`2536`、`2492` 两篇填的是日文原文（文件头自己标了「（日文原文）」），另有零散未翻译的内心独白；语体统计必须避开这些行。
4. **日文汇总比中文少 3 篇**：10028 两篇 + 1629 第 1 篇没有日文对照。
5. **卡面清单有脏数据**：1258 / 1565 / 1891 的实装日期是占位值 `2100-10-31`；1498 与 1891 资源名重复；10001 / 5002 / 1891 / 90021 的卡面名是英文或回退名。
6. **饭仓 = 父亲旧乐队成员**，现为唱片公司对接人，是父亲线的间接通道（1876 第 2 篇）。
7. **她的语言识别度来自句末装饰而非口头禅**：`わ`（约 44）/`かしら`（约 46）/`わね`（约 31）/`のね`（约 22）/`のよ`（约 11）/`てちょうだい`（约 5）；**全篇无「あはは」，笑一律是「ふふ」**（约 32 处）。
8. **称呼规则的唯一越级让步**：对外一律「姓氏＋さん」，只有 Roselia 四人与**日菜**直呼其名；成年后对队友绝不加「ちゃん」（仅幼年回忆用「リサちゃん」）。
9. **中文改编的风险**：官中把 `わ/のよ/かしら` 软化成「呢/吧/哦」，会在中文里凭空增加少女感；02 号给出了「软助词配额」硬指标。
10. **10 条世界观口径冲突**已登记（D1–D10），含赛事命名三套并存（All Fes／オルフェス／AMF）、卡面时序与主线时序错位、三个阶段划分口径互不相同。
